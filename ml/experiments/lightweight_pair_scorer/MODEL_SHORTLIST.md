# Lightweight pair scorer shortlist

Research was frozen before inference selection. The shortlist favors locally downloadable, CPU-capable, non-generative image-text scorers with identifiable weights and licenses. Expected figures below come from publishers; observed figures are from SceneMind's Windows CPU run.

UForm's model card was active through late 2024 and UForm 3.1.3 was published in 2025. Apple states that further MobileCLIP repository development is limited. The SigLIP and Jina repositories remain available and maintained through their upstream ecosystems, but neither has an evidence-based advantage for SceneMind's no-match problem.

UForm's PyTorch files total about 158 MB, while the native ONNX encoders total 60.6 MB and the publisher reports similar CPU throughput for the small model. SceneMind therefore selected ONNX directly. A local thread sweep tested one, two, four, eight and runtime-default intra-op threads. Four threads won. OpenVINO and further INT8 conversion were stopped after frozen quality failed: either may reduce latency, but cannot repair the measured positive/negative score overlap. Embedding down-casting is useful for large indexes, not for five cosine products.

## Candidate details

**UForm3 English small.** CPU is a documented first-class path. Native ONNX, PyTorch and CoreML files exist; OpenVINO can execute the ONNX graph through its ORT provider. The publisher describes pre-quantized inference support and embedding down-casting. Official throughput on a 160-core server is 325.4 images/s and 2,589.3 texts/s at batch 128; that is context only, not a laptop prediction. SceneMind observes 202.1 ms median and 229.1 ms p95 for a full top-five batch, 0.839 s load, 97.6 MB added working set with CLIP resident, and 163.1 MB isolated peak delta. Required experiment libraries are `uform==3.1.3`, `onnxruntime==1.30.0`, Pillow, NumPy, tokenizers and Hugging Face Hub. The repository has 2025 releases and hundreds of commits. Its weakness is structural: separate image/text inference produces another global similarity score, with no explicit absence classifier or pair-conditioned cross-attention.

**MobileCLIP-S0.** The official checkpoint uses a MobileOne-style MCi image tower and transformer text tower, 256 px input and the CLIP 77-token context. It emits separate normalized embeddings and a learned logit scale; no explicit match/no-match head exists. PyTorch and CoreML are supported, while ONNX/OpenVINO require user export and quantization is primarily documented for Apple deployment. The 215.9 MB file establishes a memory floor; SceneMind did not measure RAM or CPU latency because the weight terms allow research rather than product development. The published 1.5 ms image plus 1.6 ms text latency is hardware-specific and cannot be used as a Windows CPU expectation. Dependencies include the source repository, PyTorch and torchvision. The project says maintenance beyond paper reproducibility is limited.

**SigLIP base patch16-224.** This is a ViT-B/16 and text-transformer dual encoder with 224 px images and a 64-token text configuration. It produces image/text embeddings and sigmoid-scaled pair logits, but no separately trained binary matching head. CPU inference is technically supported through Transformers. ONNX and OpenVINO require export, and INT8 would be post-training quantization. The 813 MB checkpoint already exceeds the preferred memory gate before activations or runtime; SceneMind therefore recorded no local RAM/latency. Libraries are Transformers, PyTorch, SentencePiece and, for conversion, Optimum/ONNX Runtime or OpenVINO. The upstream model repository remains active. Its key weakness here is cost without a change from dual-encoder discrimination.

**Jina CLIP v1.** This English long-text dual encoder uses a 224 px vision tower and accepts up to 512 text tokens. It scores cosine similarity and has no explicit match/no-match output. CPU, PyTorch and ONNX paths exist; shipped ONNX choices include full, fp16, int8, uint8, q4 and bnb4 variants. OpenVINO would require conversion. The full checkpoint is 891 MB; the two int8 ONNX towers total about 226 MB before runtime. SceneMind recorded no local RAM/latency because even the compact variant retains custom remote model code and the same dual-encoder limitation. Required libraries include Transformers or Sentence Transformers plus trusted repository code, or ONNX Runtime with matching tokenization. The model repository remained active into 2026.
